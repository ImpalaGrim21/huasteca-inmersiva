## Producción del producto turístico

ECC **no añade directamente** reservas, inventario, autenticación, separación de negocios, pagos, gestión hotelera ni una base de datos a Huasteca. Tampoco convierte fotografías en 360°, aumenta la precisión de OpenStreetMap o mejora automáticamente el rendimiento GPU de Three.js. Su manifiesto lo presenta como un conjunto de skills, MCP y convenciones de desarrollo ([manifiesto Codex, líneas 1–30](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.codex-plugin/plugin.json#L1-L30)).

Huasteca dispone hoy de React 19, TypeScript estricto, Vite 7 y Three.js, una guía espacial, atlas y estudio con persistencia en `localStorage`. El build ya ejecuta TypeScript y Vite. GitHub Pages ya usa Node 22, `npm ci`, una base de proyecto y publicación de `dist/`. Estas propiedades se verifican en los archivos locales `package.json`, `tsconfig.json`, `.github/workflows/deploy-pages.yml` y README. Los informes `docs/qa.md`, `docs/qa-ux-v2.md` y `docs/qa-guide-v3.md` documentan el alcance de cada comprobación; no constituyen una certificación de explotación comercial.

La contribución razonable de ECC sería reducir regresiones antes de publicar. La preparación para un servicio comercial seguirá requiriendo implementar y probar los sistemas que el negocio necesite. El catálogo de prompts no reemplaza ese trabajo.

## Codex y Windows: compatibilidad real

**El plugin nativo Codex no equivale a la integración Claude.** El manifiesto apunta a los skills, `.mcp.json` y `hooks/codex-hooks.json`; este último contiene únicamente **SessionStart**. No conecta los hooks Claude de formato tras editar, typecheck, Stop ni las guardas de herramientas. El README del adaptador lo reconoce y exige revisar/confiar el hook ([manifiesto, líneas 25–29](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.codex-plugin/plugin.json#L25-L29), [hook completo](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/hooks/codex-hooks.json), [adaptador, líneas 64–86](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.codex-plugin/README.md#L64-L86)). La documentación oficial actual también indica que instalar un plugin no confía automáticamente sus hooks ([OpenAI: revisión de hooks](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)). No se ha instalado ni probado el adaptador en este host.

El entrypoint PowerShell es real: comprueba Node >=18 y delega a Node. Si falta `node_modules`, ejecuta **`npm install --ignore-scripts`**, no una simple copia de Markdown ni `npm ci`. Bloquear lifecycle scripts es una protección útil, pero sigue descargando dependencias y no sustituye la revisión de los programas que después ejecuta ([install.ps1, líneas 37–77](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/install.ps1#L37-L77)).

La parte opcional de continuous-learning sigue dependiendo de shell: `observe-runner.js` busca Bash y, si no lo encuentra, emite un aviso y devuelve salida exitosa sin observar. Esto puede parecer una instalación correcta aunque esa función esté omitida ([runner, líneas 115–141](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/observe-runner.js#L115-L141)). La receta de verificación también es Bash. La compatibilidad del core Node no demuestra compatibilidad de cada skill en PowerShell.

Hay una inconsistencia comprobada de documentación: README dice que los defectos Windows **#2489 y #2626 están abiertos**; la API los devuelve cerrados como `completed`, desde agosto. El código de `memory-vault.js` ya contiene la corrección del caso `dev=0`. Por tanto, **no se presentan esos defectos históricos como fallos actuales comprobados**; tampoco su cierre demuestra la ausencia de otros problemas Windows ([README, líneas 1310–1332](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/README.md#L1310-L1332), [corrección, líneas 124–139](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/memory-vault.js#L124-L139), [#2489](https://github.com/affaan-m/ECC/issues/2489), [#2626](https://github.com/affaan-m/ECC/issues/2626)).

## Hooks, configuración y datos: riesgos concretos

- **No confundir aviso con bloqueo.** `quality-gate.js` omite lenguajes/herramientas no disponibles y, aun en modo strict, registra fallos sin devolver por sí solo una decisión de rechazo. `post-edit-format.js` puede escribir código con `--write` y trata errores como no bloqueantes. No reemplazan el build de CI ni una suite de aceptación ([quality-gate, líneas 61–107 y 144–152](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/quality-gate.js#L61-L152), [formatter, líneas 42–87](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/post-edit-format.js#L42-L87)).
- **El runtime automático tiene efectos materiales.** El código de consentimiento enumera escrituras de fuente, control de procesos, texto de transcript enviado a LLM, actividad MCP, permisos y registros. La instalación gestionada exige una elección de hooks; es una protección real que debe conservarse ([hook-consent, líneas 12–36](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/install/hook-consent.js#L12-L36), [líneas 403–416](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/install/hook-consent.js#L403-L416)).
- **La variante Codex home afecta al entorno del usuario.** El adapter destina archivos a `~/.codex` y usa `user-config.example.toml`. Ese ejemplo contiene búsqueda live, `terminal-notifier`, seis MCP con `npx` —varios sin versión o con `@latest`— y perfiles explícitos strict/yolo. `yolo` declara `approval_policy="never"` con `workspace-write`; no es un sandbox totalmente abierto y definir el archivo no lo activa. Aun así, copiarlo cambiaría decisiones de entorno ajenas al objetivo. Hay lógica de preservación de configuraciones editadas; no se afirma que el instalador las sobrescriba indiscriminadamente ([adapter](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/install-targets/codex-home.js#L7-L42), [referencia de usuario, líneas 17–100](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.codex/user-config.example.toml#L17-L100), [yolo](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.codex/yolo.config.toml), [preservación](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/install/codex-user-config.js#L35-L55)).
- **MCP adicional y dependencia externa.** El plugin nativo incorpora Chrome DevTools mediante `npx -y chrome-devtools-mcp@1.10.1`. Está fijado, pero implica descargar/ejecutar otro paquete y añadir una segunda superficie de navegador. No aporta por sí solo una ventaja demostrada sobre nuestro navegador/Playwright existente ([.mcp.json](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.mcp.json)).
- **`security-scan` es otro producto.** El skill invita a instalar/ejecutar `ecc-agentshield`; la revisión profunda usa API Anthropic. Ese paquete no fue auditado aquí y sus resultados no pueden atribuirse a esta revisión de ECC. No conviene activarlo automáticamente ([skill, líneas 30–98](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/skills/security-scan/SKILL.md#L30-L98)).

Se observan buenas medidas: versiones fijadas en dependencias directas, integridad en los 203 registros de dependencias del lockfile leído, instalador con lifecycle scripts deshabilitados, consentimiento de hooks, chequeos de rutas/configuración, y CI de ECC con Actions fijadas por SHA y credenciales de checkout no persistentes. Son controles concretos, no una garantía de seguridad del catálogo completo ([package.json, líneas 544–574](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/package.json#L544-L574), [workflow, líneas 29–91](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/.github/workflows/reusable-test.yml#L29-L91), [política SECURITY](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/SECURITY.md#L91-L106)).

## Encaje con nuestra memoria y QA

La memoria vigente exige una ficha vinculada al chat y revisiones explícitas mediante `memoria.ps1`. **No adoptar los hooks ECC de continuidad ni unified-memory para este trabajo.** `session-start.js` busca primero coincidencia por worktree y después por repositorio o nombre de proyecto, e inyecta también instincts globales. No utiliza nuestra vinculación de ficha por chat. Aunque marca los resúmenes anteriores como históricos, introduciría otra fuente de continuidad y reglas aprendidas ajenas al aislamiento solicitado ([selección, líneas 292–363](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/session-start.js#L292-L363), [inyección, líneas 691–745](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/session-start.js#L691-L745)).

En la integración Claude completa, `session-end.js` extrae contenido de transcripts y escribe resúmenes. Opcionalmente, según umbral/intervalo, llama a `claude -p` para resumir: el helper envía hasta 7.000 caracteres de conversación, usa `haiku` por defecto y reutiliza la autenticación local. Esto añade procesamiento externo y consumo; no es una memoria local neutral. **Este hook Stop no está conectado en el manifiesto nativo Codex leído**, por lo que no se afirma que instalar ese manifiesto produzca automáticamente dicha salida ([session-end, líneas 223–247](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/hooks/session-end.js#L223-L247), [llm-summary, líneas 1–26 y 119–196](https://github.com/affaan-m/ECC/blob/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b/scripts/lib/llm-summary.js#L1-L196)).

Nuestro QA de navegador y revisión independiente ya cubre parte de la propuesta ECC. Lo que vale añadir es una suite reproducible de flujos críticos, baseline visual estable y revisión de teclado/a11y, sin sustituir los skills locales de navegador ni crear otros sistemas de memoria. Al medir escenas animadas, fijar estado de cámara, datos y movimiento para evitar falsos cambios de captura.

## Propuesta de adopción verificable, todavía no ejecutada

1. Mantener esta evaluación como referencia y extraer sólo los seis métodos anteriores en una guía breve adaptada al proyecto; conservar sus atribuciones cuando se reutilice contenido sustancial. No copiar el AGENTS global, profiles ni MCP de ECC.
2. Elegir una regresión real y una entrega futura comparables. Implementar sólo la automatización necesaria: flujos de estudio/guía, persistencia, navegación, fallos de recursos/WebGL, teclado y una captura estable móvil/escritorio. Mantener `npm run build` como comprobación obligatoria.
3. Registrar por entrega tiempo de desarrollo y revisión, defectos detectados/escapados, repeticiones por pruebas inestables, tamaño del bundle y mediciones de render en el mismo dispositivo. Registrar tokens/coste sólo cuando estén disponibles de forma fiable. No atribuir mejoras a ECC sin comparación.
4. Adoptar únicamente lo que muestre utilidad. Dejar fuera instalación full, observer/instincts, vault, global sync, yolo, MCP duplicados y servicios Pro hasta que haya una necesidad concreta y revisión de su superficie.

**Decisión de esta revisión:** ECC ofrece material útil para disciplinar QA y revisión. No aporta una mejora demostrada de producción o productividad por instalarlo; para Huasteca, la mejor relación entre valor y riesgo es la adopción selectiva de métodos con pruebas propias, manteniendo memoria, permisos y herramientas actuales.
